# ROD Private ECDSA Adaptor Signature v1

## Experimental Byte-Level Specification

**Status:** Derived from implementation, not an official specification from the repository author.  
**Frozen implementation:** `bellodox/rod-web-swap@cb136d791c836c704a122278d00c7bfefde1a8b0`  
**Wire compatibility:** Deliberately records the wallet's private variant; not compatible with DLC/`secp256k1-zkp` DLEQ proofs.

## 1. Scope

This document specifies the single-signer ECDSA adaptor-signature primitive implemented by `js/ecdsa-adaptor.js` and its nonce helper in `js/coin.js`.

It specifies a **hardened conformance profile**. For valid canonical inputs, outputs are byte-identical to the wallet. For malformed points, scalars, and encodings, this specification requires rejection even where the current wallet parser is permissive. The security argument applies only to this hardened domain.

## 2. Parameters

All elliptic-curve operations use secp256k1:

```text
p = FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEFFFFFC2F
n = FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141
a = 0
b = 7
```

`G` is the standard secp256k1 generator. The group generated by `G` has prime order `n` and cofactor 1.

Lowercase letters denote integers modulo `n`. Uppercase letters denote curve points. Point addition is written `+`; scalar multiplication is written by juxtaposition.

## 3. Primitive encodings

### 3.1 Scalars

`Scalar32(v)` is the 32-byte unsigned big-endian encoding of integer `v`.

Normative ranges:

| Field | Range |
|---|---|
| Signing secret `x` | `1 <= x < n` |
| Adaptor witness `y` | `1 <= y < n` |
| Main nonce `k` | `1 <= k < n` |
| Proof nonce `w` | `1 <= w < n` |
| ECDSA value `r` | `1 <= r < n` |
| Pre-signature scalar `s'` | `1 <= s' < n` |
| DLEQ challenge `c` | `0 <= c < n` |
| DLEQ response `z` | `0 <= z < n` |

Any serialized scalar outside its range MUST be rejected before curve arithmetic.

### 3.2 Points

`Point33(P)` is the canonical 33-byte SEC 1 compressed encoding of non-infinity point `P`.

A point decoder MUST:

1. Require exactly 33 bytes.
2. Require prefix `0x02` or `0x03`.
3. Require encoded `x < p`.
4. Recover a square root satisfying `y^2 = x^3 + 7 mod p`.
5. Reject infinity and failed square roots.
6. Require canonical reserialization to equal the input.

Because secp256k1 has cofactor 1, a valid non-infinity curve point is in the prime-order subgroup.

Hybrid, uncompressed, infinity, truncated, extended, and non-canonical encodings MUST be rejected.

### 3.3 Messages and auxiliary randomness

`m_bytes` MUST be exactly 32 bytes. `m = OS2IP(m_bytes)`; arithmetic involving `m` is reduced modulo `n`.

`aux` MUST be exactly 32 bytes.

### 3.4 Concatenation

`||` denotes unambiguous byte concatenation. Every item in every transcript below has a fixed length, making the encoding injective over the accepted domain.

## 4. Tagged SHA-256

For UTF-8 tag `tag` and byte string `data`:

```text
tag_hash = SHA256(UTF8(tag))
TaggedHash(tag, data) = SHA256(tag_hash || tag_hash || data)
```

The protocol uses:

```text
ECDSAadaptor/aux
ECDSAadaptor/non
DLEQ
```

The `DLEQ` tag is used for two roles. Their input lengths are disjoint:

| Role | Input length |
|---|---:|
| Proof nonce | 163 bytes |
| Proof challenge | 198 bytes |

This prevents literal cross-role input equality, but separate versioned tags are recommended for a future protocol revision.

## 5. Key generation

### 5.1 Signing key

Choose `x` uniformly from `[1, n-1]` and compute:

```text
X = xG
```

### 5.2 Adaptor statement and witness

Choose `y` uniformly from `[1, n-1]` and compute:

```text
Y = yG
```

`Y` is the public adaptor statement and `y` is the adaptor witness.

## 6. Main nonce derivation

Inputs: `Scalar32(x)`, `Point33(Y)`, `m_bytes`, and `aux`.

```text
aux_hash = TaggedHash("ECDSAadaptor/aux", aux)
masked_x = Scalar32(x) XOR aux_hash
nonce_hash = TaggedHash(
    "ECDSAadaptor/non",
    masked_x || Point33(Y) || m_bytes
)
k = OS2IP(nonce_hash) mod n
if k == 0: k = 1
```

The `k = 1` fallback is wallet-compatible. A future revision SHOULD abort instead because a zero reduction is a negligible exceptional event and failing is easier to analyze.

## 7. Private DLEQ proof

The prover proves knowledge of `k` satisfying:

```text
R' = kG
R  = kY
```

### 7.1 Proof nonce

```text
proof_seed =
    Scalar32(k) ||
    Point33(Y) ||
    Point33(R') ||
    Point33(R) ||
    aux

w = OS2IP(TaggedHash("DLEQ", proof_seed)) mod n
if w == 0: w = 1
```

### 7.2 Commitment and challenge

```text
A1 = wG
A2 = wY

challenge_transcript =
    Point33(G) ||
    Point33(Y) ||
    Point33(R') ||
    Point33(R) ||
    Point33(A1) ||
    Point33(A2)

c = OS2IP(TaggedHash("DLEQ", challenge_transcript)) mod n
z = (w + c*k) mod n
```

The proof is `(c, z)`.

### 7.3 Attestation

Given canonical `G`, `Y`, `R'`, `R`, `c`, and `z`:

```text
A1* = zG - cR'
A2* = zY - cR
```

Reject if either reconstructed commitment is infinity. Recompute `c*` from the exact challenge transcript above and accept only if `c* = c`.

### 7.4 Difference from the DLC proof

The DLC/`secp256k1-zkp` challenge hashes:

```text
Point33(R') || Point33(Y) || Point33(R) || Point33(A1) || Point33(A2)
```

This private variant prepends `Point33(G)` and places `Y` before `R'`. Proofs are therefore not interoperable.

## 8. Adaptor pre-signature generation

Inputs: signing secret `x`, adaptor point `Y`, message `m_bytes`, and auxiliary randomness `aux`.

1. Derive `k` using Section 6.
2. Compute:

```text
R' = kG
R  = kY
r  = x_coordinate(R) mod n
```

3. Reject if `r = 0`.
4. Compute:

```text
s' = k^(-1) * (m + r*x) mod n
```

5. Reject if `s' = 0`.
6. Generate private DLEQ proof `(c,z)` using Section 7.
7. Return pre-signature:

```text
pre = (R, R', s', c, z)
```

The implementation SHOULD verify its own serialized output before releasing it.

## 9. Serialization

The pre-signature is exactly 162 bytes:

```text
offset   length   field
0        33       Point33(R)
33       33       Point33(R')
66       32       Scalar32(s')
98       32       Scalar32(c)
130      32       Scalar32(z)
```

There is no algorithm identifier or version byte in the deployed format. Implementations MUST negotiate the variant out of band. A future revision MUST add explicit versioning before changing any transcript.

## 10. Pre-signature attestation

Inputs: signing public key `X`, adaptor point `Y`, message `m_bytes`, and serialized pre-signature.

1. Strictly decode all points and scalars.
2. Verify the DLEQ proof from Section 7.
3. Compute `r = x_coordinate(R) mod n`; reject if `r = 0`.
4. Compute:

```text
Q = (s')^(-1) * (mG + rX)
```

5. Accept only if `Q = R'`.

## 11. Completion

Inputs: valid pre-signature and witness `y` for `Y = yG`.

```text
s = s' * y^(-1) mod n
if s > n/2: s = n - s
r = x_coordinate(R) mod n
```

Output strict DER encoding of ECDSA signature `(r,s)`. The transaction layer appends its separately validated sighash byte.

## 12. Recovery

Inputs: valid pre-signature, strict DER completed signature `(r,s)`, and adaptor point `Y`.

The completed signature's `r` MUST equal `x_coordinate(R) mod n` before recovery is accepted.

Compute:

```text
y0 = s' * s^(-1) mod n
```

Return:

```text
y0       if y0*G = Y
n - y0   if (n-y0)*G = Y
failure  otherwise
```

The second case handles low-S normalization.

## 13. Mandatory error behavior

All failures MUST be fail-closed and MUST occur before state transitions, funding, or secret-scalar multiplication on externally supplied points.

Reject:

- invalid key and point encodings;
- scalars outside their canonical range;
- message or auxiliary data of incorrect length;
- signatures not exactly 162 bytes;
- infinity in proof reconstruction;
- failed DLEQ proofs;
- failed pre-signature equations;
- non-minimal or trailing-data DER;
- completed signatures with mismatched `r`;
- recovered witnesses not mapping to `Y`.

## 14. Test-vector conformance

An implementation conforms when it:

1. Generates every positive vector exactly from the listed private inputs.
2. Verifies every positive vector.
3. Completes to the listed DER signature.
4. Recovers the listed witness.
5. Rejects every negative vector.
6. Rejects the exhaustive one-bit mutation corpus.

The canonical corpus is `vectors/private-adaptor-v1.json` in this bundle.

## 15. Security profile declaration

Conformance implementations MUST declare:

```text
Protocol: ROD Private ECDSA Adaptor Signature v1 (experimental)
Curve: secp256k1
Hash: SHA-256 tagged hashing
Message length: 32 bytes
Pre-signature length: 162 bytes
Base ECDSA profile: strict DER and low-S
Security domain: canonical prime-order points only
Composition exclusion: no ECDH, ElGamal, or CDH-dependent use of signing key X
```

Conformance is not a claim of protocol-level atomicity or production approval.
