# AGENTS.md

This file provides guidance to agents when working with code in this repository.

- This repo is a static browser wallet: there is no root [`package.json`](package.json) and no build step. Run [`tests/run-fast.sh`](tests/run-fast.sh) during development and [`tests/harness/run-all.sh`](tests/harness/run-all.sh) (after `npm ci` plus `npx playwright install --with-deps chromium` in `tests/harness/`) before release. The fast gate checks release wiring, explorer contracts, adversarial protocol cases, wallet races, and deliberate negative-control mutations. The full gate additionally drives the real unmodified app in headless Chromium, proves the PWA shell can reload offline, independently re-verifies every broadcast, and covers happy / asset-refund / payment-refund / reload scenarios on every ordered pair of distinct certified chains. A change that cannot be exercised by these gates deserves a new scenario rather than a manual click-through.
- For one real-browser settlement case, run from [`tests/harness/`](tests/harness/) `ASSET_CHAIN=LTC PAYMENT_CHAIN=DOGE SCENARIO=happy node e2e-swap-test.js`; use `SCENARIO=altrefund` for payment refund and `RELOAD_TEST=1` with `SCENARIO=happy` for reload persistence. [`tests/harness/run-all.sh`](tests/harness/run-all.sh) is intentionally sequential because fixed ports and timing-sensitive swaps make parallel runs unsafe.
- [`SHA256SUMS`](SHA256SUMS) is the release inventory. After the final source or documentation edit, run `node tests/update-checksums.js`, then rerun the fast gate. Never hand-edit the manifest or restore the obsolete `sha1sum` file.
- [`tests/harness/unit-browser-test.js`](tests/harness/unit-browser-test.js) is the fast gate (seconds, not minutes) for chain constants, fee/dust policy, and protocol invariants. Add to it before reaching for the full e2e matrix.
- Runtime depends on script-tag order in [`index.html`](index.html): crypto/libs load before [`js/coin.js`](js/coin.js), and [`js/coin.js`](js/coin.js) loads before [`js/coinbin.js`](js/coinbin.js). Do not convert to deferred/reordered loading without rechecking all globals.
- [`js/chain-registry.js`](js/chain-registry.js) is the only authoritative source for chain/network constants, API defaults, swap certification, refund/confirmation defaults, fees, relay/dust policy, and certification vectors. [`js/coin.js`](js/coin.js), [`js/otc-chains.js`](js/otc-chains.js), the wallet menu, mock chain, and settlement matrix must derive from it. Never restore copied chain tables or hard-coded test-chain lists. Wallet/explorer behavior assumes the compiled defaults unless Settings changes API endpoints at runtime; `engine.applyApiConfig()` propagates saved per-chain API bases and backend types to live profiles.
- The wallet is intentionally offline-first but not fully offline: address generation/signing are local, while balance, UTXO, tx lookup, broadcast, and API health depend on the ROD API wrappers in [`coinjs.addressBalance()`](js/coin.js:419), [`coinjs.transaction().listUnspent()`](js/coin.js:1197), [`coinjs.transaction().getTransaction()`](js/coin.js:1239), and [`coinjs.transaction().broadcast()`](js/coin.js:1322).
- Broadcast and lookup handlers expect JSON-RPC-style `{result,error}` envelopes from the ROD API, not legacy Coinb.in/Chain.so payloads; preserve that normalization when editing API code.
- Wallet login compatibility is deliberate: deterministic open-wallet derivation in [`#openBtn`](js/coinbin.js:137) must remain stable for existing users, even though the flow is labeled less secure.
- SegWit support is intentionally split: new-address tools expose SegWit/Bech32, but the wallet access flow hides those controls in [`index.html`](index.html) and forces legacy by default in [`syncWalletSegwitState()`](js/coinbin.js:250) startup wiring for current API compatibility. Separately, Dogecoin has **no SegWit at all** — `coinjs.supportsSegwit()` returns false for it, the SegWit controls are hidden, `getWalletAddressType()` forces legacy, and [`chainsModule.publicKeyToAddress()`](js/otc-chains.js) throws rather than mint a `doge1…` address nothing would accept.
- Settlement coins use one registry and one adapter contract. [`js/chain-registry.js`](js/chain-registry.js) owns each profile; [`js/otc-explorer.js`](js/otc-explorer.js) owns explorer normalization. There are no separate "major" and "small coin" packages. A certified coin can occupy either `terms.assetChain` or `terms.paymentChain`; its role is selected per swap. Adding a compatible chain means adding one complete profile, independent vectors, and any genuinely new explorer driver—not branches or duplicate constants in protocol/UI/test code.
- Protocol v2 uses `assetChain` / `paymentChain`, generic funding/claim/refund fields, Nostr kinds `7341` and `31341`, and the `spexSwapV2*` storage namespace. Protocol-v1 orders, events, configs and live sessions are intentionally not migrated, displayed, imported or resumed. Do not restore the old `rodOtc*` keys or `rod/alt` canonical fields.
- ROD remains the control plane even when it is not a settlement leg: ROD identity, reputation, name ownership, order publication/discovery, and `releaseRodHeight` remain ROD-specific. Settlement transaction helpers must use `assetChainOf(session)` / `paymentChainOf(session)` or the corresponding canonical terms, never infer a chain from the role.
- Refund safety is a **wall-clock** relationship, not a block count: the payment refund matures first and the asset refund remains later by the safety margin. The ROD control-plane release window must also leave enough time before the payment refund. Each chain expresses its timeout in its own blocks; do not add a chain by copying another chain's block count.
- Fee guidance is local-only in this fork. Keep the relay-floor logic centered on [`ensureWalletFeeMeetsRelayFloor()`](js/coinbin.js:463) and the offline estimate in [`feeStats()`](js/coinbin.js:2369); do not reintroduce remote fee estimators.
- Developer donation is intentionally disabled by default: [`coinjs.developer`](js/coin.js:22) is empty and [`#developerDonation`](index.html) defaults to `0`. Guard any donation-related change against emitting invalid outputs.
- [`js/otc-explorer.js`](js/otc-explorer.js) normalizes Esplora, BlockCypher, Blockchair, and Blockbook into one Esplora-like contract in integer base units; its request coalescing is in-flight only, not a TTL cache, because stale swap-critical data is worse than extra requests.
- [`js/otc-engine.js`](js/otc-engine.js) has several non-obvious invariants: jQuery 1.9 `.then()` exceptions do not become rejections, so async builders must return rejected Deferreds explicitly; large hex payloads live in separate `spexSwapV2Hex_*` localStorage keys; ROD wallet identity is derived even when another wallet tab is visible; and self-published relay events are intentionally marked seen to prevent echo corruption of signature slots.
- [`js/coinbin.js`](js/coinbin.js) uses balance-request epochs to stop late callbacks from overwriting the active wallet UI, and forces legacy address type for non-SegWit chains, especially Dogecoin.
- Be careful when changing scripts or assets used by the PWA shell: update the cache list in [`sw.js`](sw.js) (and bump `STATIC_CACHE_VERSION`) and keep CSP/connect restrictions aligned in [`_headers`](_headers) — a new explorer backend needs its host added to `connect-src` or every request from the deployed PWA fails silently.
- Existing project history in [`CHANGELOG.md`](CHANGELOG.md) is the best source for non-obvious compatibility constraints and previously verified wallet behavior.
